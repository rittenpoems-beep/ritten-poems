一个人，
三种手艺。

研究技术的人、做内容与影像的人、在讲台上把复杂问题讲简单的人。这三件事在我这里不是三份工作，而是同一条路上的三种动作。

我没有大厂履历，也不是传统意义上以手写代码为核心竞争力的资深程序员。我的专业是数据科学与大数据技术，目前还在本科阶段。我真正花时间的地方，是持续跟踪前沿工具，弄清楚它们为什么这样工作，再把这份理解变成能用的东西、别人也能学会的知识。

所以我的日常经常是分裂的：上午在调一个 Agent 的记忆结构，下午在剪一条给普通人看的视频，晚上在改课程讲义里的一个例子。它们看起来不是一件事，但背后的动作是一致的——先理解，再拆解，然后动手验证，最后讲清楚。

工具放大的是你已经拥有的判断力，不是它缺席的部分。

这也是我为什么不愿意把自己定死在一个头衔上。AI 教育者、内容创作者、Agent 实践者，这些词都只说对了一部分。更准确的说法也许是：一个还在学习、但愿意把学习过程公开出来的人。

两门课、一套讲义、一次次半小时的免费讲解。目标不是让你记住名词，而是让你能判断结果。

03Technology / 技术

不是听来的，
是自己趟出来的。

我讲的每一个机制，背后都有真实动手过的系统。Varve 是我独立主导设计的开源记忆系统；视频生产线则来自我自己的内容制作。它们都不完美，但边界清楚。

Open source / MITPython · SQLite FTS5 · PowerShell

Varve

AI Agent 的跨会话记忆系统

会话一结束，AI 编码助手就丢了环境认知、项目状态和做过的判断。Varve 用环境、状态、历史三层结构处理这件事：只注入最新状态，细节按需检索，注入落在请求尾部，不破坏 prompt 缓存。

4,539会话请求
≈14亿累计输入 token
96%Prompt 缓存命中率
Environment相对稳定的事实：项目结构、依赖、约定、外部系统。变化慢，检索成本低。
State当前局面：正在做什么、试过了什么、结论是什么。以尾部追加的方式注入。
History完整发生过的对话与工具轨迹，索引进 FTS5，需要时定位回来。

这本创刊号，
为什么长这样。

给翻到这里的人：

把个人网站做成一本杂志，不是为了显得特别。是因为我一直觉得，一个人做过的事不应该被削成几行技能标签。作品有它的语境，课程有它的边界，失败和未完成的部分也应该有位置。

这本创刊号的结构很简单：先交代我是谁，再分别打开教育、作品、技术、手记四个抽屉。中间插了一页立体的别册，提醒自己：做东西的快乐，和它有没有用是两回事。

我没有把网站写满。没有虚构的客户，没有借来的评价，也没有把还在进行中的事说成已经完成。如果你在这里看到某个空白，那通常是因为我还没有真实材料可填。

如果你也在学 AI，或者想做出点什么，可以从一次半小时的免费讲解开始。不需要先决定什么，我们先把问题聊清楚。
